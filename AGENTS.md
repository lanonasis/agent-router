# AGENTS.md

- The dev-only auth bypass in `apps/onasis-agent-haven/src/contexts/AuthContext.tsx` must stay gated on `import.meta.env.DEV` (and its sessionStorage flag ignored otherwise) — production builds must always require a real auth-gateway session.
- Lovable builds from the monorepo root: root `package.json` must keep `build`/`build:dev` delegating to `apps/onasis-agent-haven`, root `tsconfig.json` extends the app's `tsconfig.app.json`, and the app's Vite `outDir` is the root `dist` — hosting runs `tsc` and reads output there.
- The router's operator activity trail (`services/onasis-ai-router/core/activity-log.js` in memory, `core/activity-store.js` on disk) is fed only by the existing ops events, stays metadata-only (no prompts, answers or credentials), persists settled entries as daily JSON-lines files pruned by `ROUTER_ACTIVITY_RETENTION_DAYS`, and is tenant-scoped unless the caller's org is in `ROUTER_OPS_ORG_IDS` — so history survives restarts and is shared by every replica without exposing tenant data.
- The Agent Playground's model calls run only in the `supabase/functions/agent-playground` backend function (Lovable AI, key server-side) and require an Onasis credential verified against the auth gateway's `/v1/auth/resolve` — credits are never spent anonymously and the Onasis auth flow stays the single identity source. Personas and tools are composed from `packages/agent-model-files` (role docs, SOUL.md, policies.md, tools.md), never hand-copied.
- The app's Vite `envDir` is the monorepo root, because Lovable Cloud writes its `VITE_SUPABASE_*` values to the root `.env`.
- The dashboard reads the router address and optional API key from `apps/onasis-agent-haven/src/lib/routerSettings.ts` (browser override over `VITE_ROUTER_URL`); every router call must go through it so Settings, topology and activity never disagree.
