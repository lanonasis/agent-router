# 2026-02-22 — Security Audit & Deployment

## Architecture Decision

**Confirmed 3-service setup is correct** for personalization/branding goal:
- `api-gateway` → Unified entry point, traffic routing
- `auth-gateway` → Auth boundary (never merge with AI execution)
- `ai-router` → AI + memory + tools (security-sensitive)

**Key insight**: Separation enables personalization (memory bank + auth context + tool execution). Not accidental complexity — necessary for the goal.

## Security Hardening Complete

Applied **14 patches** to ai-router:

### Critical (3)
- Command injection → `execFile()` + executable allowlist
- Path traversal → `_resolveRestrictedPath()` sandbox
- Shell injection → Args array + character validation

### High (5)
- Race condition → `_prefetchInflight` Map
- `node-fetch` vulnerability → Native `fetch` + `AbortController`
- Unhandled rejections → `try/catch` in memory tools
- CORS wildcard → `ALLOW_DEV_CORS=true` opt-in
- Error leak → Generic messages in webhook

### Medium (6)
- Circuit breaker decay (prevents flaky vendors)
- Tool summarization PII stripping
- Log sanitization middleware
- Audit logging for `code.write`
- Health endpoint cleanup (removed internal URL)
- Production rate limiting (Redis/Supabase option)

## Lessons

1. **3 services < 100+ redirects** — Aggregation reduced bloat while keeping security
2. **Security requires isolation** — AI execution (code tools!) must be separate from auth
3. **PM2 cleanup**: `pm2 kill` → `pm2 delete all` → backup `~/.pm2` → `pm2 update`
4. **Redis for rate limiting**: Cluster-safe, prevents bypass on restart
